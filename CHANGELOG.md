# Changelog

All notable changes to **rap-plus**.

## [Unreleased]

### Added — rap-big-logo extension
Enlarged **"RAP"** startup header (`extensions/rap-big-logo/index.ts`). Replaces Pi's built-in header (the small `▀▀█` logo + keybinding hints) with a 5-row block-letter "RAP" logo in the active theme's accent color, plus a `rap-plus` version label and a compact keybinding hint line. Rationale: Pi's built-in logo is a hardcoded 2-row half-block glyph whose size is structural — `BuiltInHeader` assumes exactly two lines (`const [top, bottom] = piLogoLines()`), so it cannot be enlarged in place; `ctx.ui.setHeader()` swaps the whole header for a custom component that can draw an arbitrarily large logo at runtime. Theme-aware via `theme.fg("accent", ...)` (renders in the signature blue under `rap-bluemon`, recolors automatically on theme change); output cached per-theme and cleared by `invalidate()`. Pure runtime, so it survives `pi update` (unlike `scripts/patch-pi-logo.sh`, which only recolors the now-hidden built-in logo). Auto-applies on `session_start` in TUI mode. Commands: `/rap-logo` (re-apply), `/rap-logo off` (restore built-in header). Registered in `package.json` → `pi.extensions`.

### Added — rap-toolgate extension
`/rap-settings` command (`extensions/rap-toolgate/index.ts`) — per-extension on/off toggle for provider-quota savings. Each tool-bearing extension's tool declarations (name + description + JSON schema) enter the system prompt on every request (~140 tokens/tool); disabling an extension prunes its tools from the active set via `pi.setActiveTools()` so they leave the prompt, while the extension itself stays loaded (commands/event handlers still work). Toggle state persists globally in `~/.pi/agent/rap-settings.json` (absent key = enabled) and applies to every session including new ones. The prune is idempotent — `setActiveTools(getActiveTools().filter(t => !disabled.has(t)))` only removes disabled-extension tools (never adds), and only acts when a disabled tool is actually active, so it's a no-op once pruned and safe to run every turn. Re-applied on every `before_agent_start` so it self-heals after plan-mode or other tool-set changes. Tool→extension mapping is derived dynamically from `pi.getAllTools()` grouped by `sourceInfo.path` (so the toggle list auto-adapts and only shows extensions that actually register tools — non-tool extensions have ~0 fixed per-request cost and are intentionally omitted). `/rap-settings` (no args) opens an interactive `/settings`-style select panel (`ctx.ui.select` loop): pick an extension to flip its state, the list refreshes with updated ON/OFF + savings labels, repeat; **Esc saves & exits** (no "Done" button — each flip persists immediately). Quick forms: `/rap-settings <id> on|off`, `/rap-settings all on|off`. Registered in `package.json` → `pi.extensions`.

### Changed — rap-bluemon theme persistence moved to rap-theme-bluemon.json
The rap-bluemon theme choice is now stored in a rap-owned global file `~/.pi/agent/rap-theme-bluemon.json` (shape `{ theme: "rap-bluemon" }`) instead of Pi's `settings.json.theme`. `writePiThemeSetting` now writes only `rap-theme-bluemon.json` (atomic temp-file + rename); `readPiThemeSetting` reads the rap file first and falls back to `settings.json.theme` for backward compatibility with pre-move installs. A new `applyRapThemeOnStart()` runs on every `session_start` and applies the saved theme via `ctx.ui.setTheme()` if it differs from the active one — so every new session auto-loads the theme from `rap-theme-bluemon.json`. Rationale: gives rap-plus a dedicated, rap-owned global config file (consistent with `rap-settings.json` for extension toggles) that survives `pi update`s and is independent of Pi's core `settings.json`. No flash risk because the persisted theme name is the constant `rap-bluemon` (dark/light both resolve to it).

### Theme — rap-bluemon
The `rap-bluemon` theme is a vivid cobalt-blue dark theme:
- `themes/rap-bluemon.json`: primary blue `#4f9eff`, blueBright `#79c0ff`, fg `#d6dde3`, canvas `#0d1117`, borders `#1c2d44`/`#16233a`, semantic green/red/yellow/orange/purple/pink/cyan, diff backgrounds, and export `pageBg`/`cardBg`/`infoBg`. `dim` uses `#768494`.
- `extensions/todo/ui/theme-palette.ts`: the centralized chrome palette (status-bar powerline gradient, frame, status-segment foreground tints, working-shimmer text) — a 7-step vivid cobalt-blue gradient (model→cost) preserved as Bluemon's signature, spanning the selection blue (`#1a4480` family) toward the primary blue (`#4f9eff` family). Frame `#2a4060`; working text `#d6dde3`/`#929eab`. No algorithms, role names, types, or APIs changed.
- All other extensions render through `theme.fg(...)` / theme tokens (or return plain text/markdown) and pick up the theme automatically — no per-extension code changes needed.
- Non-TUI artifacts left untouched on purpose: `rap-lens/lensmap.ts` standalone HTML report CSS and `install.sh` shell-log ANSI colors are outside the terminal theme surface.

### Logo recolor — portable via npm `postinstall`
Pi's startup logo (`▀▀█` / "Pi" wordmark) uses hardcoded brand colors in its bundled chunk (`dist/bundle/chunks/*.js`) and is NOT themeable. Added `scripts/patch-pi-logo.sh`: an idempotent, version-robust, non-fatal script that locates the chunk by scanning for the brand-coral signature `rgbColor(228,138,122)` (independent of the chunk's build-hash filename) and rewrites the three logo triplets to rap-bluemon blue: `CORAL #4F9EFF`, `BLUE #1F6FEB`, `YELLOW #79C0FF`. The package's `postinstall` hook runs it automatically — Pi's package manager invokes `npm install` (no `--ignore-scripts`) for both `npm:` and `git:` sources, so the logo is blue on the first `pi` launch with no manual step, for any install method. The script targets the GLOBAL Pi install (via `npm root -g`, with a PATH-walk fallback that skips copies under the package's own `node_modules`), so it patches the Pi the user actually runs even when npm drops a local peer copy that shadows `pi` on PATH during postinstall. Re-run `sh ~/.pi/agent/extensions/rap-plus/scripts/patch-pi-logo.sh` after `pi update` (which restores Pi's original bundle) — or rely on the runtime auto re-patch (see below). Safe: if the signature is absent (already patched, or a future Pi changes the logo colors) the script is a silent no-op; it never exits non-zero, so a postinstall failure can never block installation.

The rap-bluemon extension (`core/logo-patch.ts`, wired into `session_start`) **auto re-patches at runtime**: on each `pi` start, if the running Pi version differs from the last one it verified (via a tiny marker at `~/.pi/agent/.rap-plus-logo-patched.json`), it re-scans the global bundle chunk and re-patches if the brand-coral signature is back. This closes the gap where a `pi update` (Pi core) restores the original logo without bumping rap-plus's version (so postinstall would not re-fire). Cheap in steady state (one marker read, no scan); does real work only once per Pi version. Limitation: a file patch can't affect the already-loaded process, so the first session after a `pi update` shows the default logo once (the file is patched in the background via `setImmediate`), then subsequent sessions are blue — no manual command. Non-throwing and targets the global Pi install (via `npm root -g`, skipping local `node_modules` shadows), mirroring the install-time script.

### Added — extensions
- **rap-plan-mode** — read-only planning mode (`/rap-plan`, `/rap-todos`). Removes edit/write tools via `setActiveTools`; blocks destructive bash via the `tool_call` event. Plan widget with `[DONE:n]` progress, persistence, `Ctrl+Alt+P` shortcut, `--plan` flag.
- **rap-subagents** — agent delegation via the `subagent` tool: single, parallel (max 8 tasks / 4 concurrent), and chain (max depth 3) modes. Agent discovery from `~/.pi/agent/agents` + nearest `.pi/agents`. Safety: `RAP_SUBAGENT_DEPTH` env propagation, stderr redaction, trust gating, `SIGTERM`→`SIGKILL` abort.
- **rap-simplify** — review & simplify git-diff changed code (`/rap-simplify`). Detects changed files, constructs a scoped review instruction, sends to the session agent. Regression-safe (no silent edits).
- **rap-code-review** — automated + on-demand code review (`/rap-review`). Auto-injects a language-aware checklist after edits (via `tool_result`/`turn_end`/`before_agent_start`); on-demand `/rap-review` calls `ctx.modelRegistry.complete` for structured severity findings (CRITICAL/HIGH/MEDIUM/INFO), parsed from JSON with tolerant fallback. Read-only.
- **rap-lens** — diagnostics + code intelligence (`/rap-lens`, `/rap-lens-map`, `lens_*` tools). TypeScript type-check (`tsc --noEmit`), multi-compiler/linter parsing (tsc/rustc/gcc/ruff/flake8), triage marks; LSP navigation (goto-definition/find-references/hover) via the TypeScript LanguageService; symbol discovery (search/module-report/read-symbol, regex fallback); ast-grep structural search/replace; autofix (TS codefixes + eslint --fix + prettier --write); HTML module-map generator. New modules: `lsp.ts`, `symbols.ts`, `astgrep.ts`, `autofix.ts`, `lensmap.ts`.
- **rap-debug-mode** — evidence-first debug workflow (`/rap-debug`, `debug_checkpoint` tool). Six-stage methodology (investigate→hypothesize→probe→reproduce→fix→verify); fix stage gated behind confirmed reproduction.
- **rap-agent-ide** — guarded IDE assistance (`ide_search`, `ide_diff`, `ide_edit_guarded`, `ide_terminal`, `ide_debug_run`, `ide_debug`, `ide_system_metrics`, `ide_cpu_profile`). Guarded editing, ripgrep search, git-diff inspection, persistent terminal pool, CDP debugging (`node --inspect-brk`), and observability (system metrics + CPU profile). New modules: `terminal.ts`, `cdp.ts`, `debugging.ts`, `observability.ts`.
- **Shared utilities** (`extensions/_shared/`): `safety.ts` (severity parsing, path resolution, secret redaction, truncation, dedup), `subprocess.ts` (argument-array execution, timeout/cancellation, output cap), `git-diff.ts` (diff parsing/formatting), `bash-allowlist.ts` (destructive-command detection). Pure modules for unit testability.
- **rap-lens full surface**: LSP navigation (`lens_goto_definition`, `lens_find_references`, `lens_hover`); symbol discovery (`lens_symbol_search`, `lens_module_report`, `lens_read_symbol`); ast-grep (`lens_ast_grep` RO + `lens_ast_grep_replace` mutating, with dynamic binary detection that rejects the system `sg`/newgrp); autofix (`lens_autofix`); `/rap-lens-map` HTML module-map generator.
- **rap-agent-ide full surface**: terminal pool (`ide_terminal`: persistent shell sessions — create/send/list/output/kill, sentinel-based output capture); debugging over CDP (`ide_debug_run` + `ide_debug`: breakpoint/resume/step/evaluate/locals/stop); observability (`ide_system_metrics` via `node:os`; `ide_cpu_profile` via the CDP Profiler domain → `.cpuprofile`).
- **ast-grep** (`@ast-grep/cli`) added as an optional dependency for `lens_ast_grep`.
- `/rap-todo clear` command: wipe all todos (completed + unfinished) with confirmation.
- `typecheck`, `test`, `test:integration` npm scripts.
- `allowImportingTsExtensions: true` in `tsconfig.json` (required for Node 24 native type stripping).
